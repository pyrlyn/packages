## What this project is

The sync contracts and the Kotlin sync client of the creator's paid cloud: a Kotlin Multiplatform
port of `crates/sync-proto` and `crates/sync-client` from [backend](https://github.com/pyrlyn/backend).
The server side lives in `apps/backend-kotlin` (`services/sync`), the apps (rtok-kotlin and
others) use the client.

| Module | Coordinates | What |
| --- | --- | --- |
| `proto` | `pyrlyn.sync:proto` | The contracts in `proto/contracts`, `grpc.health.v1` and `google.rpc`, generated by kotlinx-rpc; `StatusDetails`, the rich error model (`ErrorInfo`, `BadRequest`, `QuotaFailure`, `RetryInfo`) |
| `client` | `pyrlyn.sync:client` | `SyncClient`, `LocalStore`, `TokenSource`, `StoredToken`, `DeviceLogin`, `SecretStore`, `SyncException`, `AuthException` |
| `testing` | `pyrlyn.sync:testing` | `Mem`, an in-memory `LocalStore`, and `stored`, for the tests of this package, the server and the apps |

## How it is used

Nothing is published. A consumer includes this build (`includeBuild`) and depends on
`pyrlyn.sync:<module>`; Gradle substitutes the projects. It also needs JetBrains' `kxrpc-grpc`
repository for the kotlinx-rpc modules (see `settings.gradle.kts`).

## Build and test

Needs JDK 21 and `shared-settings` and `kotlin-kit` in the workspace's `packages/` (found in any
directory above the build, so a nested worktree works; or `SHARED_SETTINGS_DIR`, `KOTLIN_KIT_DIR`).

```bash
./gradlew check        # tests on the host's native target, ktlint, detekt
./gradlew ktlintFormat # fix formatting
```

The client against the real server is tested in `apps/backend-kotlin`
(`services/sync` `KotlinClientTest`).

## Rules

- Code, docs, comments and commits in English.
- `./gradlew check` must pass, with warnings as errors.
- The files in `proto/contracts` stay byte for byte those of `../backend/proto`, so Rust and
  Kotlin clients and servers keep talking to each other.
- Targets: macOS arm64, Linux x64 and arm64. kotlinx-rpc's gRPC does not build for Windows yet.
- gRPC links BoringSSL, which clashes with the OpenSSL libcurl links on Linux: the client talks
  HTTP only through kotlin-kit's `http` interface, and the app picks an engine that does not
  link OpenSSL beside gRPC.
- Everything the server, the auth server or the local store returns is untrusted input: a bad
  answer becomes a `SyncException` or `AuthException`, never a crash. A token never reaches a
  log or an exception message (`Secret`).
